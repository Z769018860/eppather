The complete 36-row comparison is checked into [the CSV](data/six_project_bounded_source_eppather.csv), and [the LaTeX table](data/six_project_bounded_table.tex) is ready for a scoped RQ subsection. The CSV preserves caller initialization and the exact per-row boundary, so a reader can recompute each comparison.\n\n## Reproduction and counting

Run `python3 tools/six_project_fixed_witness.py --cnip build/cnip --output-dir six-project-results` after building Eppather with `ANALYSIS_BACKEND=epat++`. The CI uses `cnip -q --maxloop 6 --maxpaths 20` on a separate fixed-input entry per row. The driver instruments **source extracted from this repository**, executes original and instrumented versions with GCC undefined-behavior sanitizer, and compares observable source output/state, including the list node links and the SDS allocation header type. The corresponding Eppather entry uses caller-owned arrays to represent the specific source fields/bytes. Subtract only the enumerated caller array initialization writes (list 7, inih 8, SDSLib 3, cJSON 3, tinyexpr 2). Scalar initialization contributes no array accesses. The Lua workflow independently subtracts 10 caller array writes and uses `--maxloop 3`.

One direct field or array-element read/write contributes one MEMS; a compound update contributes one read and one write. The Lua `memcpy` contract contributes one read and one write per byte. No analyzer wall-clock results or DP speed comparison are asserted. The original function's behavior is checked against its instrumented copy; the Eppather array projection is justified within the enumerated paths and source operation mapping, not proven equivalent over unconstrained inputs.

The exact cJSON input strings are `"X"`, `" X"`, `"   X"`, `"    "`; the last input includes the NUL within its passed length and exercises the decrement after reaching the buffer length. The tinyexpr `te_compile` call constructs an actual expression tree for the instrumented `te_eval` witness, but compilation/optimization/freeing and recursive expression evaluation are **outside the measured boundary**. The cJSON counting explicitly excludes memory accesses inside the `can_access_at_index` and `buffer_at_offset` macros and parser calls, even though they execute in the original helper. The corresponding Eppather fixture counts exactly the same **direct-field subtotal**. Consequently the cJSON number 15 is not a complete helper count or a parse-call estimate. Its numerical equality with the older, unrelated legacy cJSON model value 15 is coincidental.

The list witness uses caller-provided nodes and does not include `list_new` allocation. The SDSLib witness instruments `sdssetlen`'s header flag access/header update as well as the byte write in `sdsclear`; setup and `sdslen` afterward are excluded. The inih projection separates the loop-bound and source-byte conditions to preserve the original C short-circuit access behavior: an initial, direct `i < size - 1 && src[i]` fixture produced Eppather overcounts on short-circuit exits. The generated branch-specialized fixed entries contain only the paths reachable at the recorded 1–3 size bounds. The Lua reader's positive-refill branch, callback accesses, and larger buffers remain unmeasured.

## Negative controls and legacy model validity

The [ablation artifact 10873577427](https://github.com/Z769018860/eppather/actions/runs/36155822291) records that removing Lua's byte copy or ZIO state updates makes 9 of 16 fixed cases differ from the original; removing cJSON's whitespace offset advance changes three of four tested states; replacing tinyexpr's constant read with zero changes all three tested source fragment results. The cJSON source input `xxxx` fails to parse while the legacy LLM summary reports success when an external `parse_success=1` is supplied; the tinyexpr source evaluates `1+2` to 3 while the legacy LLM summary returns ASCII 49. These are negative controls, not values to average with the calibrated projections.

### Text suitable for the RQ section

> To assess whether source-guided function projections preserve access counts, we instrumented bounded source paths in six repositories and checked output/state against unmodified implementations. On 36 fixed-input witnesses (list 3, inih 9, SDSLib 2, cJSON 4, tinyexpr 2, and Lua 16), the access counts of the corresponding Eppather projections matched their source witness under a common counting contract. The observed within-grid maxima were 9, 7, 3, 15, 2, and 13, respectively. The cJSON and tinyexpr rows measure a direct-field subtotal of a whitespace helper and the constant case of the evaluator, respectively; they do not estimate complete parse or evaluation calls. Lua covers the reader-returns-EOZ domain. Hence these measurements demonstrate bounded path fidelity of the stated projections, not unbounded original-function MaxMEMS or accuracy of the historical LLM-generated models.

Do **not** place the six maxima in an unqualified `MaxMEMS by project` chart. A paper figure should label each source boundary and use paired source/Eppather values per case, with cJSON and tinyexpr in separate scoped panels or marked `fragment only`. The failure corpus denominator remains the 193 collected failures; none of these fixed-input witnesses adds to it.
